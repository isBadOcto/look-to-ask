# Codex 桌面交接与验收

2026-10-25 按用户要求简化：**一次主屏截屏＋同帧注视局部图**，不再识别应用/窗口或判断遮挡。截图会包含当时主屏上可见的应用及桌面。API 模式仍只发送原来的局部双图。

## 完整操作流程

1. 退出旧 Look to Ask，从源码目录双击 `run.cmd`。当前源码包含直接截屏改动，旧 0.5.0 安装包尚未更新。
2. Codex 保持运行并登录。Look to Ask →「发送目标 / API / 语音设置」→ Codex 桌面对话 → 填写专用对话链接 →「检查 Codex 对话」→ 保存。检查只读，不发送问题。
3. 开始并完成校准，保持摄像头运行。点击准备语音模型，等待“已就绪”；完全退出后须重新校准。
4. 最小化到托盘以便后台使用。可以看浏览器、编辑器、图片或桌面，无须最大化、选择或整理应用窗口。
5. 看向目标，按住 Ctrl+Alt+V 或 Ctrl+Alt+Space 说话，松开。普通摄像头抖动不再阻断提问。
6. 按下时冻结最近真实注视点的中位数，隐藏自己的标记和界面，截取一次主屏；生成概览与原像素局部图。只有一个新鲜预测时也能触发；录音期间移动目光不会改目标。
7. 松开立即关闭麦克风，本地识别完成后自动把问题和两图加入绑定的 Codex 对话。不再手动点击发送。固定提示词使用英文，用户问题保留原文，回答仍遵循用户提问的语言。
8. 在 Codex 查看问题、两张附件和回答。本应用不读取回答、不额外通知，使用 Codex 原生提醒。

「检查对话」「快捷键自检」「测量精度」不会发送。Ctrl+Alt+A 是文字提问：预览后仍需手动发送。

## 怎样判断是否工作

正常状态：正在录音 → 麦克风已关闭/正在本地识别 → 正在交给 Codex → 已交给 Codex。

用 `tests/manual/targets.html` 的左上、中心、右下目标分别提问。每次概览应是触发时的主屏，黄色框对应局部图，回答应指向框内对象。一次录音中移动目光后，仍应使用按下时的位置。两图同帧；松开时不会重新截屏。

后台语音不恢复主窗口、预览或注视标记。托盘可以打开控制面板、重新校准、停止摄像头、真正退出；无系统托盘时保留任务栏入口。错误状态可从托盘提示或控制面板查看。

## 错误与兼容性

- 完全没有有效注视点、数据过期或语音模型未就绪：明确提示，本次不发送。不用鼠标位置或固定中心冒充注视点。
- 主屏/DPI 改变：重启、重新校准；不冒用失配的坐标。125%、150%、200% 缩放仍需实机验收。
- 系统无法截屏、图片编码失败：不发送。普通窗口重叠不再被拒绝。
- 对话无效、组件不兼容：不转到其他对话或备用 API。
- 发送确认丢失：状态不确定，先检查 Codex，不能自动重发。
- 已入队不能从本应用撤回；唤醒失败时请打开目标对话，避免重复发送。
- 录音中取消、停止摄像头、重校准或退出：关闭麦克风，丢弃迟到转写。

当前桌面协议适配曾验证 Windows 包 26.1021.2667.0、自带 Codex 0.164.0-alpha.11.1。版本更新后需重新检查；原生通知及点击定位取决于 Codex/Windows 设置，需人工验证。

## 隐私

摄像头、语音识别本地完成；麦克风只在按住时打开。截图、音频、个人校准不由本应用落盘，不持续截屏。Codex 模式主动发送整张主屏概览、局部图及转写，其他显示器不捕获。PNG 通过本机 stdio 内存交接；**Codex 自身会保留队列及聊天附件/历史**。

没有新增数据库、Agent 框架、MCP 或运行依赖。不复制登录凭据，不用开发助手的工具作为运行依赖，不启动另一个生成回答的 CLI 会话。

## 可自动执行的检查

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe tests/manual/check_screen_capture.py
```

上述检查不向 Codex 发送问题。真实截图检查只捕获 tests 内的全屏纯色夹具，不保存图片，不代表摄像头/麦克风问答通过。

如需再次验证真实队列，下面命令会向指定的专用测试对话发送三组生成的双图和问题：

```powershell
.\.venv\Scripts\python.exe tests/manual/check_codex_handoff.py --thread "codex://threads/你的测试对话ID" --send-fixtures
```

只有实际对话收到三组图片且对应回答正确，才能确认该版本交接工作；不能仅凭“已入队”宣称回答已完成。
